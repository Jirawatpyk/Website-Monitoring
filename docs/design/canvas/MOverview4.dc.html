Spec · Phone Overview answers three things, in order: anything to do now (banners — same rules as desktop), what is wrong and is it mine (Live issues), and is the rest fine (“x/y OK” in the header, “All N sites” row → Sites). Live issues: same inclusion and sort as desktop; each row = status + one reason + Since; a neutral outline chip with the user icon shows when you own the site (“Yours”) or are its backup (“Backup”) — never accent/violet, which status badges reserve for Maintenance (spec §11). Third count by role: Responder / Admin → “Yours” (Live issues you own or back up; chips “Yours” / “Backup”, user icon) · AM (Stakeholder) → “Your clients” (Live issues on sites of clients you manage; chip “Your client”, users icon) — they act on client updates · CEO (Stakeholder, no clients) and Viewer → “Uptime 30 d”, no chips. Chips are neutral outline, never accent/violet (status badges reserve it for Maintenance, spec §11). Viewer is read-only: banners and rows open the incident without Acknowledge; AM and CEO can acknowledge but don’t need to (spec §18). Use VIEW AS to compare. Not on phones: site tiles, KPIs MTTA / MTTD / uptime, Recent events (Incidents tab), legend, sparklines. All OK → one line “Nothing needs you”. The User guide icon comes back to the top bar with the guide. “Maintenance & mutes · N active · N scheduled ›” under “All N sites” comes with the maintenance slice (§23) and opens the phone Maintenance list; left out when nothing is active or scheduled.
