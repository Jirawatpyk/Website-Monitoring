SPEC NOTE · MAINTENANCE & MUTES · ROUTE /maintenance Where it sits. Sidebar Operations › “Maintenance”. Overview has the short “Maintenance & mutes” card and a header “Maintenance” button that open this page. “Schedule maintenance or mute” opens the existing Maintenance dialog with Site empty; End now and Edit / cancel are the same dialogs as before (reason required, logged). Sections. Active now (maintenance windows and mutes together, ending soonest first) · Waiting for approval (starting soonest first) · Scheduled (starting soonest first) · Recent · last 30 days (newest first). A section with nothing in it is left out; with nothing active, waiting or scheduled the page shows the empty card and Recent. Badges (§11). Active maintenance = the site status badge, accent soft calendar — the only accent badge. Active mute = the real status badge plus the overlay “Muted · until 18:00” (neutral outline eye-off). Needs approval, Scheduled and every Recent state are neutral outline; the icon says the kind (calendar = maintenance, eye-off = mute). Approval. Asked for in the Maintenance dialog (Responder, over 24 h → “Ask for approval”). Maintenance longer than 24 h asked for by a Responder waits for an Admin (an Admin’s own starts as scheduled). Approve → moves to Scheduled, the asker gets a Chat message. Decline needs a reason → Recent “Declined”, the asker gets the reason. Nobody approves before the start → it doesn’t start; Recent “Not approved — didn’t start”. Mutes never need approval (max 24 h, start now, stop new alerts only — an open incident keeps escalating). Roles. Admin: every action on every site; on a request only Approve or Decline (to ask for changes, decline with a reason). Responder: End now and Edit on sites they own or back up, and Edit / withdraw on their own requests; other rows say who can act. AM, CEO and Viewer: read only — no row actions, no Schedule button (STATE › Read only). A running window or mute is changed with “Edit end” or stopped with End now; “Cancel” exists only before it starts. Every action adds a log line; lines are never replaced. Uptime line. Maintenance: “Not counted in uptime” (removed from the window, client status page shows “Planned maintenance”). Mute: “Still counted in uptime”. Times are site-local Thailand time; past rows keep their log line (who, when, reason). Sample data. Fri 25 Sep 10:07 (14:40 in STATE › End mute · open incident); sites, people, times and reasons are mock data — compute them; never copy.
