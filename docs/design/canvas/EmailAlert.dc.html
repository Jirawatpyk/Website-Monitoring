Spec note — threading (FR-07) One subject per incident: site · Tier · incident id, the same for every event, so replies never fork the thread. The first email’s Message-ID is stored; every later email sets In-Reply-To and References to it. The status word goes first in the preheader and the body, so it still shows in a phone notification. PROBLEM thread: same rules, its own subject (e.g. Fuji Links · Tier 2 · INC-0141). PROBLEM, ACKNOWLEDGED and RECOVERED all reply to the first PROBLEM email. A site that fails again while the incident is open stays in the same thread. Flapping: RECOVERED emails are held like the Chat replies; one summary email goes in the incident thread after 15 min of continuous OK. DOWN AGAIN / PROBLEM AGAIN are Chat only — no email. Auto-resolved: a PROBLEM that clears within 5 min of being flagged with no acknowledgement gets one RECOVERED email on the first OK round, saying no root cause is needed. Admin system emails aren’t about one incident: their own subject per outage with its start time (so separate outages don’t merge into one mail thread), one email when it starts, no “back up” email. Resolved email: when someone resolves the incident (always by hand), one RESOLVED email goes in this same thread to everyone emailed about this DOWN incident — for INC-0142 Arm, Ploy, Tao and Bua. Held 10 s for Undo, like the ack.
Spec note — recipients & build Recipients follow the escalation step: L0 owner by day / on-call at night · L1 backup + Tao · L2 CEO · L3 FYI to CEO + AM (Tier 1, even after an ack). The client-update track emails the AM. Each email is sent per person with its own footer. Tier 2–3 L2 (+30 min, no ack) is a reminder email to Tao only — no CEO. Ack and resolve emails are held until the 10 s Undo window closes. PROBLEM: amber, never red. L0 emails the owner only; the backup is first emailed with the 60-min reminder (+60 min, no ack). A Tier 2–3 PROBLEM outside response hours is held until 09:00. No client-update email — that track is for DOWN. Admin system emails (browser verifier unavailable, fewer than 2 probe locations) go to every active Admin — today only Tao. Maintenance emails (§24): one mail thread per window — subject site · Maintenance · start (requests: DxT Monitor · Maintenance request · site · start). Owner and backup get every action (approve and decline included), except the one who did it; every active Admin gets the request and the 12 h reminder. Only the asker’s answer DM and the 1 h reminder are Chat-only. Mutes are Chat only (≤ 24 h; owner and backup get a DM when someone else mutes their site). Every later action continues in the window’s thread with a “What changed” row; windows that are over or will never run (declined, withdrawn, cancelled, ended, ended early, didn’t start, not approved) drop the Effect and “If it’s down” rows. Only Admins get “Review request”; everyone else gets “Open Maintenance & mutes” — never an approve link in an email. The first DOWN / PROBLEM email after a mute carries a “Held by a mute” row, like the Chat card. No status-page emails yet (D-013). Table layout, inline styles, 600 px max, system fonts. Status in words and colour. Plain-text part with the same facts and links. No tracking pixels.
