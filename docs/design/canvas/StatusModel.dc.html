THE DOWN RULE · USE THIS WORDING EVERYWHERE DOWN when at least 2 of 3 locations get a hard fail (timeout, 5xx, DNS/TLS error, connection refused) on two checks in a row. The second check is an immediate recheck about 30 s after the first failure. Hard fails don’t wait for the browser verifier — it only takes a screenshot afterwards as evidence. If locations are blocked (403, 429, bot challenge), the browser verifier decides: page loads and keyword found → OK with a note; page fails → DOWN; verifier unavailable → PROBLEM (unverified). Only the primary monitor can make a site DOWN; every other monitor caps at PROBLEM.

Maintenance vs mute

Maintenance is a status: alerts suppressed and the window is removed from uptime. It is identified by the calendar icon and the word “Maintenance”; among status badges only Maintenance uses the violet accent. Mute keeps the real status and still counts.

Uptime formula

site uptime = 1 − DOWN minutes ÷ minutes in window
all sites = time-weighted across sites
  • Only DOWN minutes count. PROBLEM counts as up.
  • Maintenance is removed from both sides. Mute is counted.
  • Monitor faults are stored as no data, not downtime.

Lifecycle rules · recovery and resolve

  • Resolve is always manual once the 3 conditions are met. A DOWN never auto-resolves.
  • Only exception: a PROBLEM never acknowledged that recovers within 5 min auto-resolves (no root cause) and is hidden: “N short PROBLEMs auto-resolved in < 5 min — never acknowledged — are hidden”.
  • RECOVERED reply + email go out on the first OK round (→ Monitoring); after 2 OK rounds → Needs root cause unless written. Copy: “Needs a root cause before it can be resolved.”
  • Root cause “Unknown — keep investigating” does not meet the gate — “Unknown keeps the incident open”.

Acknowledge, resolve, undo and L3

  • Acknowledge stops L1 and L2. It does not stop the client-update track.
  • Tier 1 DOWN only: if the site is still DOWN at +60 min, L3 sends an FYI to CEO + Site AM — @mention + email, never a voice call. Tier 2–3 have no L3.
  • Ladder after ack: L2 “Cancelled · acked” · L3 “FYI at 10:48 if still down”.
  • Undo: a 10 s toast on every surface. Chat, email and webhook posts for an ack or a resolve are held until the window closes (“Posting to Chat, email and webhooks in N s — nothing is sent until then” · button “Undo · N s”). Maintenance guard

Maintenance
  • A window can’t start now, or overlap now, on a site that is DOWN or has an open incident. The form shows a blocking alert and offers Mute instead.
  • A window never hides an open incident — it stays open and keeps counting.
  • Windows over 24 h need an Admin’s approval; an Admin creating one approves it themselves (“You’re an Admin — no approval needed”). Same rule on mobile.
  • If the site is still DOWN when a window ends, an incident opens immediately.
  • “Mute instead” opens the mute sheet with the open-incident rule: “Mute stops new alerts only — INC-0142 keeps escalating until someone acknowledges.” A reason is required before Mute, Schedule or Start now.
