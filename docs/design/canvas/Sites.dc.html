SPEC NOTE · SITES LIST · ROUTE /sites Where it sits. The sidebar “Sites” item opens this page. Overview keeps its live status table for watching; this is the management list. A row (anywhere on it) opens Site detail for that site (sample: Bangkok Airways – Taiwan); a draft row opens Add site to finish setup. “Visit site” opens the site’s own URL in a new tab. The incident link goes to that incident (INC-0142 → incident page, INC-0139 → resolve, others → Incidents). Row menu warnings: Schedule maintenance on a site that is DOWN or has an open incident says it can’t start now — mute instead; Mute on a site with an open incident says “Mute stops new alerts only — INC-xxxx keeps escalating until someone acknowledges” (unacked / escalated) or “… stays open” (acknowledged, monitoring, needs root cause). “Add site” and “Add first site” are shown to Admins only — other roles don’t see them. No separate Client column: client · AM is the Site cell’s second line, and Client stays a filter. No monitor-count column. Drafts. A site saved from Add site before the checklist is complete is a draft: Status “Not monitored”, “Draft · not monitored” under the name, “—” for locations, response, uptime, expiry and checked, action “Finish setup”. Drafts are counted in “N sites” but not in “monitored” or in any uptime figure, and are sorted last. Everyone sees draft rows; only Admins can open them — Admins get “Finish setup” → Add site and a clickable row, other roles get a row that isn’t a link and the plain text “Only an Admin can finish setup” in the action area (see the mobile board, viewer Arm). The sidebar “Sites” count = monitored sites only (17 here; drafts excluded; 0 with no sites, and Incidents shows no count when there are none). Filters. Search matches site name, client name and the site’s URL (case-insensitive). Status = the real site status, “Muted” selects muted sites whatever their status, “Drafts” selects drafts; the status chips set the same filter. Tier All · 1 · 2 · 3. Owner: a person, or “Mine” = owner or backup is you. Client: one client or “Internal”. Filters combine with AND; “Clear” keeps the sort. Needs attention = an open incident (any state before Resolved) · a draft · SSL or domain due within 60 days (auto-renew certificates 30 days) · no backup owner — today 6: MuvMi, Fuji Links, ORCA Thailand, Cando Asia, WeCare Studio, EQHO Academy. Sort (options “Status”, “Name A–Z”, “Uptime 30d lowest first”, “Expiry soonest first”). Default Status: Down → Problem → Maintenance → OK → Not monitored, then Tier 1 → 3, then name A–Z. Name A–Z · Uptime 30d lowest first · Expiry soonest first; drafts last, ties fall back to the default. Checked shows the time of the last complete round (HH:MM:SS, as on Overview). Build phases. ① Built today: Status, Site (+ draft badge), Tier, Owner, Client, Checked, “Visit site”; filters Tier, Owner, Client; meta “N sites · N monitored · N drafts”; Admin-only Add site; empty state = Empty states panel 1. Change to today’s build: the Client column moves into the Site cell’s second line (client · AM) and the Owner column becomes Owner · backup. ② S06 (needs rollups): Locations, Response 24h, Uptime 30d columns and the Uptime sort. ③ When /sites/[id] ships: row click and “Open” go to Site detail — until then row click to Edit site is acceptable. Status chips, search, sort, Needs attention and Expiry are this board’s additions, to be scheduled. Sample data.
