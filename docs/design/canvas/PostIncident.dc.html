VOCA outage at night — Mon 21 Sep

Summary

VOCA went down four times between 03:12 and 04:04 on Monday — 41 minutes of downtime in total. The hosting provider restarted PHP-FPM each time an aggressive crawler pushed memory over the limit. The alert posted at once, but Tier 2 is not covered at night: escalation timers were paused until 09:00, and Ploy saw it at 08:04. The site recovered on its own; no client report came in.

Root cause · 5 whys

  1. The site returned HTTP 502 from all three locations — PHP-FPM was restarting.
  2. The host restarts PHP-FPM when it passes its 512 MB memory limit.
  3. Memory spiked because one crawler requested ~40 search pages per second.
  4. Nothing limits request rate on the search page, and it is not cached.
  5. The site was set up before we had a rate-limit standard for client sites.

Went well

  • DOWN confirmed on the immediate recheck, 31 s after the first failure.
  • Flapping merged 8 status changes into one incident and one thread.
  • One RECOVERED summary after 15 min stable, instead of one per drop.

Didn't go well

  • Nobody saw it for almost 5 hours — Tier 2 is not covered at night.
  • We learned the cause from host logs, not from our own monitoring.
  • Root cause was only logged 3 days later.
