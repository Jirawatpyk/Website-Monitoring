SPEC NOTE · OVERVIEW v2 · OPTION A · ROUTE / Jobs. Overview = what is happening now and what to do next. Sites = the list you manage (search, owner/client filters, sort, drafts, row menu, expiry). Overview has no management controls except the Admin-only “Add site” shortcut. Incident banners. One banner per DOWN incident that is not yet acknowledged (escalated or not). Acknowledging stops escalation, so an acked incident never keeps a banner — it stays in Live issues. Order: escalated first, then Tier 1 → 3, then longest down. At most 2; if more qualify, “and N more → Incidents” (N = the rest). A PROBLEM never gets a banner. Acknowledge removes the banner at once (10 s undo toast; nothing is posted until then) and the next one moves up. Use the STATE control to see 2 banners + “and 1 more”, 1 banner, none, and all OK. “Open INC-…” goes to that incident (template, sample INC-0142). Counts. Every number is computed, never typed in. “x/y OK” and the “Sites OK” KPI count monitored sites only — drafts are left out (sample: 11 monitored + 1 draft). OK = status OK; a muted site counts by its real status. Sidebar “Sites” = monitored count, as on Sites. “Open” = incidents in any state before Resolved. “3 unacked (1 escalated)”: escalated incidents are a subset of unacked. MTTA · MTTD. MTTA = DOWN incidents, all tiers. MTTD = DOWN incidents, Tier 1 only. Both show “—” with “Not enough incidents yet” until there are at least 3 DOWN incidents in the last 30 days (open or closed), and hide the “vs last 30d” change until then. Sample: 1 earlier DOWN this month, so “1 banner”, “None” and “All OK” show “—”; “2 banners + more” has 5 and shows values. Live issues. (Not the same rule as the “Needs attention” switch on Sites — that one is about setup: drafts, expiry, missing backup.) A monitored site is listed when any of these is true: status Down, Problem or Maintenance · an open incident · muted · a location warning (TLS chain error). “Blocked by bot protection, verified OK” is not an issue. Sort: Down first — escalated, then unacked, then acked — then Problem, Maintenance, OK; inside each, Tier 1 → 3, then longest “Since”, then name. Whole row opens Site detail. Nothing listed → one line “All N monitored sites OK”. Why · Since · Next step. Each row shows one reason, picked in this order: Down › Problem › Maintenance › incident waiting for root cause › location warning › muted. “Since” is the start of that same reason, always “duration” over “since HH:MM”. Next step: unacked DOWN → Acknowledge (same as the banner, same undo); acked DOWN or PROBLEM → Open INC-…; waiting for root cause → Add root cause (resolve page); location warning → View checks (Site detail); muted → View site (End mute arrives with maintenance & mutes). Response 24h. 96 points = p50 per 15-minute bucket over the last 24 h. A bucket where checks failed has no point, so the line breaks and the rest stays empty — the row already says Down, the red duration and “since HH:MM”, so no extra marker. (Uses the AURA Sparkline with “show failures: none”; see the AURA note, item 16.) The line gains a point when a bucket closes — no animation in between. p50 next to it = last completed round; “—” while down. All sites. One tile per monitored site for a glance (NOC wall). Status icon + name (wraps to 2 lines, never cut to “…” that hides which site) + p50, or the DOWN duration in red. Second line: tier and a short state (ack state for DOWN, “Slow · 15 min” for Problem). Small markers on the second line: amber shield = TLS chain error, amber bell = open incident, eye-off = muted. Icons carry status, colour only repeats it. The Tier control filters the tiles only — KPIs and Live issues always show every tier. The ⓘ legend sits on Live issues because that is where location icons appear. From AURA 5.34: build the tiles with Aura.TileGrid (columns 3) + Aura.StatusTile (status, title, value = p50 or the DOWN duration, meta = tier + short state, markers shield-alert / bell / eye-off, href) and the Response 24h line with Aura.Sparkline (failures “none”). This canvas still carries an older AURA copy, so the board draws look-alikes; in code use the components. AURA’s tile icons are circle-alert (down) and wrench (maintenance) — different from the status badges (ban, calendar); see spec §21. By role (VIEW AS). Same page for everyone; only these change. Admin / Responder: chip “Yours” or “Backup” (sites you own or back up), all actions. AM (Stakeholder): chip “Your client” on sites of clients you manage; can acknowledge (not expected to, spec §18), no “Add root cause” (→ Open INC-…), no Add site. CEO: as AM without chips. Viewer: read-only — no Acknowledge in banners or Next step (→ Open INC-…), no Add site, no chips. Chips are neutral outline with a user / users icon — never accent/violet (reserved for Maintenance among status badges, spec §11). Add site is Admin-only (spec §20). KPIs stay organisation-wide for every role. Not on this page yet. On-call card — comes back with on-call. Maintenance & mutes card and the header “Maintenance” button — come back with maintenance. Until then Recent events sits beside All sites. Sample data. Names, times, incident IDs and counts are mock data — compute them; never copy.
