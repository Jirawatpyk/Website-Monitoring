One incident, one thread

Every message is a plain text line that starts with STATE · site, followed by a card. Escalation, the client update and recovery reply in the same thread. Daily digests and the weekly summary post to DxT Website Reports (see the Weekly summary board).
Spec note — why @mentions sit in the text line • Google Chat only notifies for <users/{id}> in the message text. A name inside a card body doesn’t notify anyone. The lock-screen preview shows the text line, so it carries the state in words. • L0 mentions only the person expected to act: the owner by day, the on-call person at night. Backup and FYI people are plain text. • An incoming webhook can’t edit a card it already posted. The first card stays as it was; each reply opens with the current state. • An ack is posted only after its 10 s Undo window closes (Arm acked 10:07:40 → posted 10:07:50). • PROBLEM is amber (triangle-alert), never red. L0 = owner @mention (Tier 1 at night: the on-call person) + Alerts Space + email to the owner; the backup is plain text. A Tier 2–3 PROBLEM outside response hours is held until 09:00. • A site that fails again while its incident is open joins that thread (DOWN AGAIN / PROBLEM AGAIN) and mentions only the person expected to act now. While a site flaps (≥ 3 changes in 30 min) RECOVERED replies are held; one summary goes after 15 min of continuous OK.

A site went DOWN while muted, so its incident never alerted. When the mute ends with the incident still open, the incident’s first card posts now — the usual DOWN card with one added line — and escalation starts from now.

Current status is in the latest reply. Anyone can open it; the ack is recorded under their own Google account. Down 40 min so far — the time while muted counts in uptime.
15:00 · same moment, in the mute’s thread
text:MUTE ENDED · Bangkok Airways – Taiwan · alerts back on · INC-0154 posted (DOWN since 14:20)
Spec note• “Confirmed down” keeps the real time (14:20:36); the added line says why it’s only arriving now. Every timer (L1, client update, CEO, L3) counts from 15:00, not 14:20.• End mute dialog when a silenced incident is open: “INC-0154 (DOWN since 14:20, held by this mute) posts its first alert now and starts escalating — L1 at about 14:56 if nobody acknowledges.” (sample: ended early at 14:40; if the mute runs to 15:00, L1 is 15:15)• Outside response hours (Tier 2–3, e.g. a DxT Games mute ending Fri 18:00): the added line reads “Held by a mute until 18:00 · outside response hours — escalation starts Mon 09:00”, and the text line drops “acknowledge by”: “DOWN · DxT Games (Tier 3) · held by a mute until 18:00 · timers paused until Mon 09:00”.• Rule from decision D-036. The held line is plain text (bold allowed, no colour) — Chat cards carry no colour anywhere; the words say it.• Sample INC-0154 and Arm’s 13:00–15:00 mute (“Investigating slow booking page”) are made up for this example.
